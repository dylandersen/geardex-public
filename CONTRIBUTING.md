# Contributing to GearDex Public

Thanks for helping improve GearDex. This repository is for public product feedback, issue tracking, and macOS release feedback.

## Scope

Use this repository for:

- Web app bug reports
- macOS app bug reports
- Product feature requests
- macOS release and pre-release feedback
- Public documentation corrections for this repository

Do not use this repository for:

- Application source-code contributions
- Pull requests that include private GearDex implementation details
- Account-specific support that includes private customer data
- Public vulnerability details

GearDex product development happens in the private application repository. This public repository should stay small, readable, and focused on user-facing work.

## Issue Forms

- [Bug report](https://github.com/dylandersen/geardex-public/issues/new?template=bug_report.yml)
- [Feature request](https://github.com/dylandersen/geardex-public/issues/new?template=feature_request.yml)
- [Pre-release feedback](https://github.com/dylandersen/geardex-public/issues/new?template=release_feedback.yml)

## Before Opening an Issue

- Search existing issues first.
- Use the issue form that best matches the report.
- Keep one problem or request per issue.
- Remove private data from screenshots, logs, filenames, and copied text.
- Include enough detail for another person to reproduce or evaluate the report.

## Bug Reports

Useful bug reports include:

- Where the issue happens: web app, macOS app, or both
- For web: browser, version, and page URL
- For macOS: GearDex version, macOS version, and Mac chip if known
- Clear steps to reproduce
- Expected behavior
- Actual behavior
- Screenshots or logs when helpful

## Feature Requests

Useful feature requests include:

- The workflow you are trying to improve
- What current behavior makes that workflow harder than it should be
- The result you want GearDex to support
- Any workaround you use today

## Pull Requests

This repository is not an open-source application codebase. Pull requests may be accepted for small public-repo documentation fixes only.

Do not open pull requests that add source code, build scripts, private configuration, generated artifacts, or application internals.

## Private Reports

Do not post vulnerability details publicly. Use the private reporting process in [SECURITY.md](SECURITY.md).
